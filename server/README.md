# Бот бизнес-школы Proactive (@proactive_school_bot)

Telegram-бот для клиентов и команды школы:

- **Курсы** — каталог программ с датами, расписанием и стоимостью. Кнопка «Записаться на курс» создаёт заявку.
- **Заявки** — запись на курс или консультация: имя, телефон, вопрос. Заявка приходит в чат продавцов с кнопками «Беру», «Записан», «Отказ».
- **Ивенты** — афиша мероприятий, бронь мест, оплата переводом на карту с проверкой чека модератором, билеты с QR-кодом, проверка на входе.
- **Задачи команды** — кнопка «🗂 Задачи»: свои задачи со статусами «В работе / Готово / Риск», приёмка утверждающим («Принять» / «Вернуть»), сводка по отделам для руководителей, сообщения по RACI. Всё пишется в статусную Google-таблицу. Подробно — [docs/STAFF.md](docs/STAFF.md).
- **Мост к таблице задач** — регистрация сотрудников (`/start`, `/team`) и тестовый режим (`/test`) остаются в Apps Script статусной таблицы (папка [`bot/`](../bot)); сервер пересылает туда эти команды.
- Интерфейс на русском, узбекском (латиница) и английском.

В основе — бот ивентов [Focused](https://github.com/takhatheviking/focused-training/tree/focused-bot) того же автора: ивенты, бронь, оплата, билеты, админка и зеркало в Google Таблицу взяты оттуда без изменений. Proactive добавляет курсы, заявки, метки источника в ссылках и мост к таблице задач.
Как устроено внутри — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Запуск на сервере (Docker)

Нужен любой VPS с Linux и Docker. Хватит 1 ГБ памяти.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен. Для разработки заведите отдельного тестового бота — боевой продолжит работать как раньше.
2. Скопируйте репозиторий на сервер и перейдите в папку `server`.
3. `cp .env.example .env` и впишите:
   - `BOT_TOKEN` — токен бота;
   - `ADMIN_IDS` — свой Telegram id (узнать у @userinfobot);
   - `POSTGRES_PASSWORD` — длинный случайный пароль.
4. Запустите:

```bash
docker compose up -d --build
```

Миграции применяются при старте контейнера. Логи смотрятся так:

```bash
docker compose logs -f bot
```

Обновление после `git pull` — та же команда `docker compose up -d --build`.

## Первая настройка (в самом боте)

1. `/start` → язык → «⚙️ Админка».
2. **📚 Курсы → ➕ Новый курс** — бот пришлёт форму: название, описание и расписание на RU / UZ / EN, дата старта и стоимость. Скопируйте её, заполните и отправьте одним сообщением, потом пришлите афишу. «📋 Пример» показывает заполненную форму. Обязательно только русское название: пустой перевод заменяется русским текстом, пустая цена показывается как «по запросу».
3. **💬 Чат заявок** — создайте закрытую группу для продавцов и добавьте туда бота сами (вы должны быть в `ADMIN_IDS` и администратором группы). Бот напишет вам в личку и спросит, для чего этот чат: для заявок или для модерации чеков. Пока чат не подключён, заявки приходят админам в личку.
4. Для платных ивентов: **💳 Карта для оплаты** и **🛡 Чат модерации** (проверка чеков) — как в Focused.
5. **👥 Команда** — контролёры, которые сканируют билеты на входе, и админы.
6. **📗 Google Таблица** (по желанию) — бот сам ведёт листы «Заявки», «Все заказы» и лист на каждый ивент. Как подключить — [docs/GOOGLE_SHEETS.md](docs/GOOGLE_SHEETS.md).
7. **Задачи сотрудников** — откройте статусную таблицу сервисному аккаунту и впишите `STATUS_SHEET_ID` в `.env`: [docs/STAFF.md](docs/STAFF.md).

## Как работают заявки

1. Клиент открывает курс и нажимает «Записаться на курс» (или «📝 Оставить заявку» в меню, там есть и консультация).
2. Бот спрашивает имя (одна кнопка с именем из Telegram), телефон (кнопкой или вручную) и вопрос (можно пропустить), показывает заявку целиком и отправляет её после подтверждения.
3. В чат продавцов приходит карточка: имя, телефон, Telegram, курс, язык, источник, вопрос. Кнопки:
   - **🙋 Беру** — заявка за этим продавцом, второй «Беру» бот не примет;
   - **✅ Записан** / **❌ Отказ** — итог;
   - **↩️ Вернуть в работу** — если итог поставили по ошибке.
   Нажимать могут все участники чата заявок и админы бота.
4. Пока заявка открыта, повторная заявка на тот же курс не создаётся: клиент видит номер своей заявки.
5. Сводка: «⚙️ Админка → 📋 Заявки» и лист «Заявки» в Google Таблице.

## Мост к таблице задач

Уведомления команде (дайджест, напоминания о сроках, смена статуса) отправляет Apps Script статусной таблицы, это папка [`bot/`](../bot). Входящие сообщения бота может читать только одна программа, и после запуска сервера это он. Поэтому команды сотрудников сервер пересылает в веб-приложение Apps Script, и скрипт отвечает сам, как раньше:

| Кто | Команда | Что происходит |
|---|---|---|
| любой | `/team`, `/test …` | пересылается в таблицу. Незнакомому человеку отвечает бот, как на любой непонятный текст |
| сотрудник (есть на листе «Команда») | `/my` | раздел «🗂 Задачи» сервера (если задан `STATUS_SHEET_ID`), иначе — список задач от таблицы. У клиента `/my` — «Мои билеты» |
| сотрудник | `/start`, `/help` | пересылаются в таблицу (`/start` — только пока чат не подписан), потом бот показывает обычное меню |
| общий чат | `/start Продавцы` | подписка чата на роль |

Подключение — [bot/README.md, раздел «Сервер на aiogram»](../bot/README.md#сервер-на-aiogram). Пока вы разрабатываете на тестовом боте, оставьте `BRIDGE_URL` и `BRIDGE_SECRET` пустыми: таблица отвечает от имени боевого бота.

### Порядок переключения

1. Разработка и проверка — на тестовом боте, без моста.
2. Опубликуйте Apps Script как веб-приложение и нажмите в таблице «Бот → Подключить сервер (aiogram)»: опрос входящих в таблице выключится, появится секрет.
3. Впишите в `.env` боевой `BOT_TOKEN`, `BRIDGE_URL`, `BRIDGE_SECRET` и перезапустите сервер.
4. Откат: остановите сервер (`docker compose down`), затем в таблице «Бот → Отключить сервер» и «Бот → 2. Включить бота».

## Локальная разработка

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/) и PostgreSQL. Проще всего поднять базу из `docker compose up -d db`.

```bash
uv sync
```

```bash
uv run alembic upgrade head
```

```bash
uv run python -m app
```

Тесты идут на настоящем PostgreSQL. Тестовая база `proactive_bot_test` создаётся сама, адрес сервера можно задать в `TEST_DATABASE_URL`:

```bash
uv run pytest
```

Новая миграция после изменения моделей:

```bash
uv run alembic revision --autogenerate -m "описание"
```

## Настройки `.env`

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен бота |
| `ADMIN_IDS` | — | Telegram id суперадминов через запятую |
| `DATABASE_URL` | localhost | строка подключения PostgreSQL (asyncpg) |
| `REDIS_URL` | — | хранилище шагов диалогов; без него — в памяти |
| `TIMEZONE` | `Asia/Tashkent` | в нём вводятся и показываются даты |
| `DEFAULT_LANG` | `ru` | язык до выбора и язык чатов модерации и заявок |
| `HOLD_MINUTES` | `30` | сколько держится бронь без чека |
| `MAX_PROOF_ATTEMPTS` | `3` | сколько раз можно прислать чек после отказов |
| `MAX_TICKETS_PER_ORDER` | `5` | максимум билетов на человека на один ивент |
| `UNIQUE_AMOUNTS` | `true` | от суммы каждого заказа отнимается 1–99 сум, чтобы перевод однозначно находился в банке |
| `REVIEW_ALERT_MINUTES` | `120` | через сколько минут без решения по чеку напомнить админам |
| `SUPPORT_USERNAME` | — | контакт поддержки в /help и сообщениях о возврате |
| `PAYMENT_CARD_*`, `MODERATION_CHAT_ID`, `LEADS_CHAT_ID` | — | запасные значения; обычно задаются из админки |
| `BRIDGE_URL`, `BRIDGE_SECRET` | — | мост к таблице задач; пустые — мост выключен |
| `STATUS_SHEET_ID` | — | статусная таблица задач для раздела «🗂 Задачи»; пусто — раздел выключен ([docs/STAFF.md](docs/STAFF.md)) |
| `TASKS_SEE_ALL` | — | роли с листа «Команда», которые видят сводку всех отделов, через запятую |
| `TASKS_POLL_SECONDS` | `60` | как часто сверять статусы с таблицей |
| `GOOGLE_SERVICE_ACCOUNT_FILE`, `GOOGLE_SHEET_ID` | — | зеркало в Google Таблицу, см. [docs/GOOGLE_SHEETS.md](docs/GOOGLE_SHEETS.md) |
